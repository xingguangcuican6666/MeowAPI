本页用一条最小可用路径，带你走完一次完整的授权码流程。示例以命令行/伪代码演示，你可以据此对接任意语言。

## 前置条件

<Steps>
  <Step title="授权服务器已启用">
    管理员已开启 `oauth_server.enabled`。
  </Step>
  <Step title="已获得客户端凭据">
    你已从管理员处拿到 `client_id`，以及（机密客户端的）`client_secret`，并登记了本次要用的回调地址 `redirect_uri`。
  </Step>
</Steps>

下文用 `ISSUER` 表示 New API 的服务地址，例如 `https://your-newapi.example.com`。

## 1. 读取发现文档（可选但推荐）

一次请求即可拿到全部端点地址与能力，避免硬编码：

```bash
curl https://your-newapi.example.com/.well-known/openid-configuration
```

关键字段：`authorization_endpoint`、`token_endpoint`、`userinfo_endpoint`、`jwks_uri`、`revocation_endpoint`。详见 [发现端点](/endpoints/discovery)。

## 2. 生成 PKCE 参数

公开客户端**必须**使用 PKCE；机密客户端强烈建议一并使用。仅支持 `S256`：

```bash
# code_verifier：43~128 位随机串
code_verifier=$(openssl rand -base64 60 | tr -d '\n=+/' | cut -c1-64)

# code_challenge = BASE64URL(SHA256(code_verifier))
code_challenge=$(printf '%s' "$code_verifier" \
  | openssl dgst -sha256 -binary \
  | openssl base64 | tr '+/' '-_' | tr -d '=\n')
```

## 3. 引导用户到授权端点

在浏览器中打开授权 URL（`state` 用于防 CSRF，`nonce` 用于绑定 ID Token）：

```text
https://your-newapi.example.com/oauth2/authorize
  ?response_type=code
  &client_id=cli_xxx
  &redirect_uri=https://your-app.example.com/callback
  &scope=openid%20profile%20email
  &state=RANDOM_STATE
  &nonce=RANDOM_NONCE
  &code_challenge=CODE_CHALLENGE
  &code_challenge_method=S256
```

用户会先登录 New API（若未登录），随后看到同意页，展示你的应用名称与申请的 scope。

- **用户同意**：浏览器 302 回 `redirect_uri`，携带 `?code=...&state=...`
- **用户拒绝**：浏览器 302 回 `redirect_uri`，携带 `?error=access_denied&...&state=...`

<Warning>
收到回调后，**务必先校验 `state`** 与你发起时一致，再继续。参见 [授权端点](/endpoints/authorize)。
</Warning>

## 4. 用授权码换取令牌

`code` 单次有效，默认 10 分钟内过期。机密客户端用 HTTP Basic 传递凭据；公开客户端只传 `client_id` + `code_verifier`。

```bash
curl -X POST https://your-newapi.example.com/oauth2/token \
  -u "cli_xxx:YOUR_CLIENT_SECRET" \
  -d grant_type=authorization_code \
  -d code=THE_CODE \
  -d redirect_uri=https://your-app.example.com/callback \
  -d code_verifier=THE_CODE_VERIFIER
```

成功返回：

```json
{
  "access_token": "at_xxxxxxxx",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "openid profile email",
  "refresh_token": "rt_xxxxxxxx",
  "id_token": "eyJhbGciOiJSUzI1NiIsImtpZCI6..."
}
```

`id_token` 仅在授予了 `openid` scope 时返回。详见 [令牌端点](/endpoints/token)。

## 5. 获取用户信息

用 `access_token` 作为 Bearer 令牌调用 `userinfo`：

```bash
curl https://your-newapi.example.com/oauth2/userinfo \
  -H "Authorization: Bearer at_xxxxxxxx"
```

```json
{
  "sub": "1024",
  "preferred_username": "alice",
  "name": "Alice",
  "email": "alice@example.com",
  "email_verified": true
}
```

返回哪些字段取决于令牌被授予的 scope，`sub`（用户唯一标识）恒定返回。详见 [用户信息端点](/endpoints/userinfo) 与 [Scope 与 Claims](/concepts/scopes-and-claims)。

<Tip>
如果你只需要身份信息，验证 `id_token` 的签名与 `iss` / `aud` / `exp` / `nonce` 后即可直接读取其中的 claims，无需再调用 `userinfo`——ID Token 里已包含相同 scope 的身份 claims。
</Tip>

## 6. 刷新令牌

Access Token 过期后，用 Refresh Token 换取新的一组令牌。**Refresh Token 会轮换**：旧的立即失效，请保存返回的新 `refresh_token`。

```bash
curl -X POST https://your-newapi.example.com/oauth2/token \
  -u "cli_xxx:YOUR_CLIENT_SECRET" \
  -d grant_type=refresh_token \
  -d refresh_token=rt_xxxxxxxx
```

重复使用已被轮换过的 Refresh Token 会触发**重放检测**：该授权下的整族令牌都会被撤销。详见 [令牌](/concepts/tokens)。
